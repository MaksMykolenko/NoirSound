# NoirSound — перша контрольована група користувачів

Запрошення починаються лише після статусу **RELEASE VERIFIED — READY FOR FIRST USERS** у `NOIRSOUND_RELEASE_FINALIZATION_REPORT.md`. Зелений локальний або GitHub CI сам по собі не відкриває цей етап. Запрошення в межах фіналізації не надсилаються.

## Група і сценарії

3–5 артистів/бітмейкерів і кілька слухачів. Використовувати власні акаунти та матеріали з дозволеними правами; не змінювати ролі чи контент інших людей.

- **Артист:** увійти → перевірити зрозумілий upload access → завантажити невеликий Music або Beat → дочекатися обробки → перевірити метадані й сторінку → поділитися посиланням. Окремому учаснику запропонувати невеликий batch і перевірку порядку плейлиста.
- **Слухач:** відкрити Discover → знайти контент пошуком і фільтрами → послухати → підписатися/вподобати → додати до власного плейлиста → перезавантажити та повернутися до збереженого.
- **Мобільний сценарій:** пошук → фільтр → «Показати ще» за наявності результатів → сторінка треку → playback → меню з трьома крапками → playlist action.
- **Безперервність:** змінити мову або тему під час playback; перевірити збереження пошуку, поточного треку й черги. Відкрити та закрити fullscreen lyrics.

Не створювати масовий seed для production. Пагінацію малого каталогу перевіряти дозволеним меншим page size; відсутність достатніх даних зафіксувати як межу перевірки.

## Зворотний зв’язок

Учасник надсилає один короткий запис власнику через погоджений канал:

```text
Крок / сторінка:
Що хотів зробити:
Очікувана поведінка:
Що відбулося:
Повторюється: завжди / інколи / один раз
Пристрій, ОС, браузер:
Дата й час із часовим поясом:
Request ID (якщо показаний):
Посилання на власний контент (за потреби):
```

Не надсилати пароль, cookie, access token, signed storage URL або чужі персональні дані. Нові analytics SDK, session replay чи персональний трекінг не встановлюються.

## Реакція власника

Проблеми входу, втрати даних, приватності, upload або неможливості слухати зупиняють розширення групи. Зберегти кроки, час/request ID і перевірену версію. Для дрібних труднощів зафіксувати вплив і повторюваність. Smoke-об’єкти обліковувати за ID та очищати лише власні через чинні безпечні API.

Не відновлювати БД поверх нових записів автоматично. Application rollback можливий лише після перевірки сумісності попередніх images зі схемою; database restore потребує окремого підтвердження.
